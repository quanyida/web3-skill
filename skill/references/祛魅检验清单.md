# 祛魅检验清单（Reality Check）

**用途**：Step 5.5 必读。在完成业务定性（Step 0）与链上数据验证（Step 2-5）之后，剥离一切叙事，拷问「这项目值不值得存在、有没有人愿意付钱」。

**原则**：最冷酷、最理性、不带滤镜。不要复述官网文案，不要被白皮书话术带走。4 问中任何一问找不到证据，如实写「无公开证据」，禁止用叙事填空。

---

## Q1 — 谁真的在用？（需求真实性检验）

目的：判断「高频刚需」还是「叙事爱好者」——有多少人每天因为缺少这个东西而真正受挫。

| 检查项 | 要挖的真相 | 证据来源 |
|---|---|---|
| 日活/周活量级 | 真实用户数（官网宣称 vs 链上/平台可查数据） | 官方数据、Dune、链上合约调用、社媒活跃 |
| 用户画像 | 是目标人群（交易者/开发者/机构）还是积分/空投套利者 | 社区讨论、用户行为 |
| 使用频率 | 用户每天离不开，还是注册即流失 | 留存、重复交互 |
| 替代可得性 | 用户不用它，本来就在用别的（见 Q2） | 常识 + 竞品调研 |

**判定标准**：
- 高频刚需：用户每天/每周主动使用，离开有真实损失。
- 低频/伪需求：靠激励（积分、空投、排行榜）拉来的活跃，激励一停就流失。

**反例参考**（NeoSoul 案例）：自称服务「经济 Agent」，实测活跃事件全在体育/地缘政治（曼城赢不赢、以色列大选），核心赛道区（CRYPTO）零活跃事件 → 叙事 vs 实际。

## Q2 — 不用它用什么？（替代方案对比）

目的：用户/开发者现在是怎么解决类似需求的？NeoSoul 式方案比成熟替代品好在哪里、差在哪里？

| 用户真实需求 | 成熟替代品（2-3 个） | 替代品成本 | 替代品可靠性 | 被调研项目对比 |
|---|---|---|---|---|
| （如：AI 分析） | ChatGPT/Claude + API + 自写脚本 | $20/月 | 成熟 | 更贵？更复杂？无证据优势？ |
| （如：交易执行） | 交易所直连 / 官方 SDK / 交易机器人 | 视产品 | 有多年验证 | 覆盖更窄？不承诺收益？ |
| （如：链上数据） | Nansen / Arkham / Dune / Santiment | $99+/月 | 有真实付费用户 | 数据更少？无 API？ |

**判定标准**：
- 差异点是否对准用户真实关心的问题（赚钱/省时/信息优势）？
- 还是对准了用户不关心的概念（「可验证信誉」「信任基础设施」）？
- 若剥掉叙事后核心功能 = 已有功能组合 → 标记「包装型项目」。

---

## Q3 — 钱从哪来？（付费闭环检验）

目的：有没有真实的付费闭环？没有闭环靠什么活着？

| 检查项 | 要挖的真相 |
|---|---|
| 谁付钱 | 用户/开发者/机构，谁真的掏钱 |
| 付多少 | 定价、订阅、Gas、代币消耗 |
| 收入模式 | 手续费 / 订阅 / 数据出售 / 代币？是否闭环 |
| 无闭环时的资金来源 | 融资、代币发行、卖用户数据换激励（如「积分 = 负价格买数据」） |

**判定标准**：
- 有闭环：明确产品方收入来源，且与用户价值挂钩。
- 无闭环：靠融资烧钱 + 代币叙事 + 用户免费贡献数据换未来空投 → 标记「激励先行项目」。
- 代币已发行但产品无对标收入 → 标记「叙事定价」。

## Q4 — 消失测试（灵魂三问）

直接回答，不回避：

1. **如果这个项目明天彻底消失，谁真正感到不便或损失？**
   - 核心受损者 = 买了代币的投机者？还是每天离不开它的用户？
   - 若只有投机者受损、没有核心用户 → 产品本身没有不可替代价值。

2. **它解决的是「真问题」，还是「因为 XX 叙事才被发明出来的问题」？**
   - 判断标准：如果叙事/赛道明天不爆发，它还有用吗？
   - 真问题有独立于叙事的存在价值；发明的问题依赖叙事延续。

3. **几年后回看，它更可能是基础设施，还是被叙事推高的早期项目？**
   - 基础设施候选信号：有真实收入、核心赛道活跃、有不可替代的采用。
   - 叙事推高信号：融资/上币先于产品验证、核心赛道零活跃、无付费闭环。
   - 给出概率估计（如「85% 叙事项目 / 15% 基础设施」）和成立条件。

## 输出模板（写入报告第 3 段「祛魅结论」）

```markdown
### 祛魅结论
- **需求真实性**：高频刚需 / 低频 / 伪需求 —— 证据：______
- **替代对比**：成熟替代品 ____（成本/可靠性），本项目差在 ____ / 差异点是否对准真实需求
- **付费闭环**：有/无 —— 谁付钱 ____ / 无闭环靠 ____ 活着
- **消失测试**：明天消失受损者 = ____；真问题 or 发明的问题；叙事定价 or 产品定价
- **信息缺口**：无法验证项（如实列出）
```

## 硬规则

- 4 问缺一不可；任一问无证据 → 写「无公开证据」，禁止用官网话术填空。
- 祛魅结论与业务定性、链上数据同权输出，不得因调研对象热门/叙事宏大而软化。
- 最终结论必须给出「真问题 or 发明的问题」的明确判定 + 对研究/产品决策的含义。
